:::callout
### Migración de definiciones heredadas
La API de Plataforma y la interfaz de Chainhooks se han retirado. Esta guía explica cómo convertir definiciones v1 guardadas a v2. Si necesitas ayuda para recuperar una definición o retirar un chainhook v1 existente, [contacta con soporte](mailto:support@hiro.so).
:::

## Qué aprenderás

:::objectives
* Revisar tus definiciones v1 guardadas.
* Convertir filtros basados en predicados en definiciones de eventos v2 explícitas.
* Registrar chainhooks v2 y probar la entrega.
:::

## Requisitos previos

:::prerequisites
* [Clave API de Hiro](/resources/guides/api-keys) para la API de Chainhooks.
* Definiciones v1 guardadas, incluidos los filtros y las URLs de los webhooks.
:::

<Steps>
  <Step>
    ### Reunir tus definiciones v1

    Usa tus configuraciones guardadas o exportadas para identificar los filtros, las redes y las URLs de los webhooks que quieres migrar. Si no tienes una copia, [contacta con soporte](mailto:support@hiro.so) antes de continuar.
  </Step>

  <Step>
    ### Comenzar a mapear al nuevo formato v2

    Traduce las estructuras v1 a formatos v2 antes de crear nuevos hooks. La siguiente tabla muestra el mapeo entre las estructuras v1 y v2:

    | v1 | v2 | Notas |
    |----|----|-------|
    | `if_this.scope` | `filters.events[].type` | Sustituye las combinaciones de ámbito y acción por un tipo de evento. |
    | `if_this.actions` | `type` | `transfer` se convierte en `*_transfer`. |
    | `then_that.http_post.url` | `action.url` | v2 gestiona los secretos automáticamente. |
    | `networks.mainnet` | `network: "mainnet"` | Crea un chainhook v2 por red. |
    | `authorization_header` | Gestión de secretos de webhook | Usa `rotateConsumerSecret()` después del registro. |

    #### Ejemplo

    <CodeTabs flags="ac">
      ```json !! Legacy
      {
        "name": "stx-transfers",
        "networks": {
          "mainnet": {
            "if_this": { "scope": "stx_event", "actions": ["transfer"] },
            "then_that": { "http_post": { "url": "https://example.com/webhooks" } }
          }
        }
      }
      ```

      ```json !! v2
      {
        "version": "1",
        "name": "stx-transfers",
        "chain": "stacks",
        "network": "mainnet",
        "filters": {
          "events": [{ "type": "stx_transfer" }]
        },
        "action": {
          "type": "http_post",
          "url": "https://example.com/webhooks"
        },
        "options": {
          "decode_clarity_values": true,
          "enable_on_registration": true
        }
      }
      ```
    </CodeTabs>

    Para más detalles sobre los cambios de formato, consulta el [Filtros](/tools/chainhooks/reference/filters) guía de referencia.
  </Step>

  <Step>
    ### Crear chainhooks v2

    Register each chainhook with the SDK or REST API, mirroring the mapped filters.

    <CodeTabs flags="ac">
      ```ts !! api.ts
      const v2Chainhook = {
        "version": "1",
        "name": "stx-transfers",
        "chain": "stacks",
        "network": "mainnet",
        "filters": {
          "events": [{ "type": "stx_transfer" }]
        },
        "action": {
          "type": "http_post",
          "url": "https://example.com/webhooks"
        },
        "options": {
          "decode_clarity_values": true,
          "enable_on_registration": true
        }
      };

      const response = await fetch('https://api.hiro.so/chainhooks/v1/me/', {
        method: 'POST',
        headers: {
          'x-api-key': process.env.HIRO_API_KEY!,
          'content-type': 'application/json',
        },
        body: JSON.stringify(v2Chainhook),
      });
      ```

      ```ts !! sdk.ts
      const client = new ChainhooksClient({
        baseUrl: CHAINHOOKS_BASE_URL.mainnet,
        apiKey: process.env.HIRO_API_KEY!,
      });
      const chainhook = await client.registerChainhook(
        {
          "version": "1",
          "name": "stx-transfers",
          "chain": "stacks",
          "network": "mainnet",
          "filters": {
            "events": [{ "type": "stx_transfer" }]
          },
          "action": {
            "type": "http_post",
            "url": "https://example.com/webhooks"
          },
          "options": {
            "decode_clarity_values": true,
            "enable_on_registration": true
          }
        }
      );
      ```
    </CodeTabs>
  </Step>

  <Step>
    ### Validar chainhooks v2

    Confirma que cada chainhook esté habilitado y que tu webhook reciba los eventos esperados. Actualiza tu aplicación para procesar el formato de payload v2.

    #### Verificaciones de habilitación en v2

    <CodeTabs flags="ac">
      ```ts !! api.ts
      const response = await fetch(`https://api.hiro.so/chainhooks/v1/me/${uuid}`, {
        method: 'GET',
        headers: {
          'x-api-key': process.env.HIRO_API_KEY!,
          'content-type': 'application/json',
        },
      });

      const chainhook = await response.json();
      console.log(chainhook.status.enabled);
      ```

      ```ts !! sdk.ts
      const chainhook = await client.getChainhook(uuid);
      console.log(chainhook.status.enabled);
      ```
    </CodeTabs>

  </Step>
</Steps>

## Referencia de filtro

### Ámbitos comunes

| v1 | Acciones típicas | v2 | Detalles |
|----|-----------------|----|----------|
| `stx_event` | `transfer` | `stx_transfer` | Incluye filtros `sender` o `recipient` según sea necesario. |
| `contract_call` | n/a | `contract_call` | Añade `contract_identifier` y `function_name`. |
| `ft_event` | `transfer` | `ft_transfer` | Especifica `asset_identifier`. |
| `nft_event` | `transfer`, `mint` | `nft_transfer`, `nft_mint` | Especifica `asset_identifier`. |

Para más detalles, consulta el [Filtros](/tools/chainhooks/reference/filters) página de referencia.
